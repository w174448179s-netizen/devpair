# 执行单个子任务开发

当前执行子任务：读取 `./tasks/{task文件名}`

## 执行步骤

1. **加载规则**：读取 task 文档中「需加载的规则文件」列出的所有文件，作为权威开发标准
2. **加载参考文档**：如果 task 文档有「参考文档」节，逐一读取，获取架构设计中的接口定义、数据库表结构、数据流等细节
3. **加载踩坑记录**：如果 task 文档有「相关踩坑记录」节，逐一读取，了解已知的坑和解法，编码时主动避开
4. **确认已有代码**：查看 task 文档「已有代码」节，了解前序任务产出了哪些 Entity/Mapper/Service/枚举，可直接引用
5. **只加载显式列出的规则**：不要主动扫描 `~/devpair/rules/` 下的其他文件
6. **按步骤实现**：按 task 文档「实现步骤」中的编号顺序逐步实现，复杂逻辑（算法流程、异常处理策略、原子 SQL、LLM 调用模式）必须严格按步骤描述执行
7. **自检**：实现完成后逐条检查——代码是否匹配所有已加载规则的全部约束
8. **冲突处理**：如有冲突，优先遵循 `~/devpair/rules/` 中的规范；项目特殊例外应在 task 文档的「额外说明」中已明确标注

## 注意事项

- 生成代码前，确保已读完所有列出的规则文件、参考文档和踩坑记录
- 不要跳过任何规则文件——每个文件都包含硬性约束
- 踩坑记录是已知的坑，编码时必须主动避开，不是读完就完
- 参考文档提供设计细节（接口定义、表结构、数据流），编码时必须遵循
- 「已有代码」列出的类可以直接引用，不要重复创建
- 实现步骤中的复杂逻辑（原子 SQL、LLM 预清理、解析失败处理等）不能简化或跳过
- 代码生成后逐条对照规则自检，不是大致看看，是逐条核对
- 如果 task 文档的「额外说明」与通用规则冲突，以额外说明为准（项目特殊需求）
