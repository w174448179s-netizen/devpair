# 开发完成，知识沉淀

梳理本次开发过程中新发现的踩坑、技术经验。

## 执行步骤

1. **区分知识类型**：
   - 项目独有的临时方案 → 留存 `./tasks/` 目录，在对应 task 文档的「额外说明」中补充
   - 可跨项目复用的通用经验 → 进入下一步

2. **归档通用经验**：
   - 如果该经验对应已有规则文件 → 在对应规则文件底部补充（如 tika-constraints.md 补充新的约束）
   - 如果是新领域的经验 → 在 `~/devpair/rules/` 下新建规则文件

3. **记录踩坑**：
   - 踩坑事件记录到 `~/devpair/notes/pitfalls/{组件名}.md`
   - 格式：现象 → 根因 → 解法 → 关联规则

4. **更新索引**：
   - 如果新建了规则文件，检查 `~/devpair/AGENTS.md` 是否需要更新（通常不需要，因为 AGENTS.md 不列文件路径）
   - 确保下次 task 文档可以引用新规则

## 踩坑记录格式

```markdown
## {日期}：{一句话标题}
- **现象**：{发生了什么}
- **根因**：{为什么会发生}
- **解法**：{怎么解决的}
- **关联规则**：{对应哪个规则文件}
```
